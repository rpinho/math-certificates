[129,14,80] is the last-coordinate puncturing of [130,14,81]. Each row links to a folder containing the generator matrix and Magma file, construction parameters and guarantee, the referee’s final live-bound comparison, and original plus reproduced exact-check outputs. These are candidate lower bounds, not optimality or historical-priority claims.

To reproduce, use Python 3 (standard library only) and a C++17 compiler. Referees 3 and 4 require ARM64/NEON; referee 2 also has a scalar fallback; referee 5 uses no NEON intrinsics. Follow [REPRODUCE.md](REPRODUCE.md), with individual instructions in [ref2](checkers/ref2/README.md), [ref3](checkers/ref3/README.md), [ref4](checkers/ref4/README.md) and [ref5](checkers/ref5/README.md). All commands and paths are relative to this codetables/ folder.

For Magma, load any `generator.magma` in Magma and run `MinimumDistance(C);`; the file constructs C and asserts its dimension. The first seven Magma files are unchanged copies of the previously checked submission files, and the [106,12,72] file was generated from its generator.txt and parsed back entry for entry; the reruns use the clean-room C++ checkers in checkers/.

GF(5) entries are residues 0–4. For GF(9), a+b·t is stored as a+3b, with 0≤a,b<3 and t²+1=0 over GF(3). Addition is componentwise modulo 3; (a+bt)(c+dt)=(ac−bd)+(ad+bc)t. The integers are field encodings, not arithmetic modulo 9. Polynomial coefficient lists in construction.json run from constant term upwards.

The constructions use standard cyclic codes, Construction X, and Alltop’s Construction XX; see the [Magma construction reference](https://magma.maths.usyd.edu.au/magma/handbook/text/1979) and [Grassl’s table references](https://www.codetables.de/citation.php). SHA256SUMS covers every other file, using relative paths; it necessarily excludes itself. No external code or data is bundled.
